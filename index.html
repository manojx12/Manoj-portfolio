Sheet 02 · Foundations · Level +04.00

Break it down until it's obvious.

The board behind me is how most of my work starts: one vague problem, split into pieces small enough to build and test.

  1. Decompose first

    Draw the problem as a graph of smaller ones. Most hard bugs turn out to be two easy ones tangled together.

  2. Make it boring to run

    Clear data models, explicit API contracts, and logs you can still read at 2 a.m. I'd rather spend the cleverness on the interface.

  3. Measure, then optimise

    I run the profiler before I form an opinion. I tuned this building by measuring frame times on an integrated GPU.
